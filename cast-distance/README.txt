キャスト飛距離ログ — PWA版

公開URL:
https://aki-lua87.github.io/utility_html/cast-distance/

起動・インストール
------------------
cast-distance/ をGitHub Pagesで公開します。HTML・JS・画像をそのまま配信し、
ビルドや外部ライブラリは不要です。記録をサーバーへ送信する処理はありません。
Android Chromeの「アプリをインストール」または「ホーム画面に追加」、
iPhone Safariの共有メニュー「ホーム画面に追加」で利用できます。
「オフライン起動の準備ができました」を確認してから圏外へ移動してください。
Service WorkerはHTTPSまたはlocalhostで動作します（file://では動きません）。

マスター取得方式の比較と採用理由（2026-11-15）
--------------------------------------------
方式                      更新方法                 公開範囲・注意点
Googleの公開CSV            シート変更後に自動反映   個別シートの公開は可能。CSV解析と
                                                   実際の公開URLでのCORS確認が必要。
Apps Script API / JSONP    シート変更後、次回取得   返す列を固定でき、元ブックは非公開。
                                                   初回の所有者認証・デプロイが必要。
GitHub PagesのJSON         JSONの生成・配置が必要   同一オリジンでCORS問題なし。
                                                   自動同期には別途仕組みが必要。

採用: Apps Scriptの読み取り専用APIを、Google公式のJSONP方式で取得します。
fetchのCORS許可ヘッダーに依存せず、端末にAPIキーやトークンを置きません。
Googleからのリダイレクトはscriptタグで処理します。
アプリ用マスターのA:F（ルアー）とH:K（リール）だけを読み、必要な項目だけを返します。
釣果記録・設定・ロッド一覧にはアクセスせず、書き込み処理やdoPostはありません。
取得先のシート名・範囲・ブックIDをリクエストから変更することもできません。
所有者の認証も spreadsheets.readonly に限定しています。
SpreadsheetApp.openByIdは書き込み権限も要求するため、Advanced Sheetsサービスを使用します。

公式資料:
- 個別シートの公開: https://support.google.com/docs/answer/183965
- Content Service / JSONP: https://developers.google.com/apps-script/guides/content
- Webアプリのデプロイ: https://developers.google.com/apps-script/guides/web
- Advanced Sheets: https://developers.google.com/apps-script/advanced/sheets
- 読み取り権限: https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/batchGet

初回の手動設定（スプレッドシート全体の公開は不要）
------------------------------------------------
1. スプレッドシートの所有者アカウントで https://script.google.com/ を開き、
   新しい独立プロジェクトを作成します。既存の数式や既存スクリプトは編集しません。
2. apps-script/Code.gs の内容を新規プロジェクトのコードへコピーします。
   SPREADSHEET_IDは指定済みです。
3. プロジェクトの設定で「appsscript.json マニフェスト ファイルをエディタで表示する」を有効にし、
   apps-script/appsscript.json の内容をコピーします。
   左側の「サービス」にGoogle Sheets API v4（Sheets）が表示されることを確認します。
   標準のGoogle Cloudプロジェクトを自分で関連付けている場合は、そのCloud側でもSheets APIを有効にします。
コードを保存し、「デプロイ」→「新しいデプロイ」→「ウェブアプリ」。
   「次のユーザーとして実行」: 自分
   「アクセスできるユーザー」: 全員（匿名アクセスできるもの）
   所有者が読み取り権限を承認し、デプロイします。アプリ利用者のログインは不要です。
   組織ポリシーで「全員」が選べない場合、この方式での匿名取得は利用できません。
5. https://script.google.com/macros/s/…/exec URLをコピーします（/devは使用不可）。
   シークレットウィンドウで開き、version:1 / lures / reels のJSONが返ることを確認します。
   {"error":"Master unavailable"} ならサービス設定・所有者権限・シート名・数式エラーを確認します。
6. PWAの「マスター接続設定」を開き、URLを入力して「接続先を保存して更新」。
   「更新済み」とルアー一覧・89cm/75cm・根拠表示を確認します。
   接続先は端末ごとに保存されます。共有初期値が必要な場合だけmaster-config.jsへURLを設定してください。
7. 以降はシートのマスターを更新するだけです。PWA起動時または「マスター更新」で反映します。
   シート更新だけではApps Scriptの再デプロイやアプリ変更は必要ありません。
   Code.gs自体を変更した場合は「デプロイを管理」から同じデプロイを新バージョンへ更新します。

公開範囲:
デプロイ後は、返却されるマスター項目をURLを知る人が認証なしで読めます。
表示名・カラー・状態・メーカー・ID等に非公開情報を含めないでください。
元ブックの共有設定や「ウェブに公開」は変更しません。
JSONPは取得先のJavaScriptを実行するため、自分で作成した信頼できるURLだけを設定してください。
接続先欄を空にして保存すると、その端末の自動取得を停止できます。
公開を停止するにはApps Scriptのデプロイをアーカイブしてください。
端末に保存済みのマスターや履歴は停止後も残ります。

選択・保存の動作
----------------
- 表示名はシートのアプリ表示名を使用。選択中の重量・カラー・IDも補足表示します。
  同名項目が複数ある場合、プルダウンに重量・カラー・IDを付けて区別します。
  数字のルアーIDも文字列として保持し、再採番しません。
- 「その他（自由入力）」で名前を入力し、1投を保存すると端末の一覧にも登録されます。
  重量とカラーは名前に含めてください。Googleには書き込みません。
- リールも「その他（カスタム）」で名前と巻上長を入力できます。名前省略時は「カスタム」です。
  登録後は端末のプルダウンから再選択できます。同名で別の巻上長を登録する場合は名前で区別してください。
- NFKC正規化・前後空白除去・連続空白の統一で同名の重複を避けます。
  同名のマスターがあればそちらを優先し、カスタムを重複表示しません。
- リール切り替えで基準巻上長を自動入力。手動変更もでき、変更状態と元の根拠を記録します。
  初期値: エクスセンスBB C3000MHG 89cm（メーカー公称）、
          SEASIR P Prospec C3000SDH 75cm（暫定推定・未実測）。
- 前回選択・入力途中のカスタム名・手動の巻上長を復元します。更新中も操作できます。
  基準値のまま使っているリールは新しい基準値に追従し、手動変更した値は維持します。
- ルアーの状態は「あり」「なし」の2値です。更新済みの「アプリ用マスター」の抽出結果を使い、
  さらにPWAでも「あり」だけを一覧へ採用します。「なし」や旧状態・空欄は表示しません。
  前回選択したルアーが抽出結果から消えた場合も復活表示せず、現在の一覧から選び直します。
  リールだけは、マスターから消えた選択を「前回の選択」として保持します。
  履歴の名前・管理ID・重量・カラー・根拠は当時のスナップショットで、後から書き換えません。

オフライン・保存データ
----------------------
起動直後から最後の正常なマスター（なければ初期マスター）で操作できます。
接続先が設定されていれば毎起動時に最新版を要求し、正常な応答だけをキャッシュします。
取得失敗・12秒のタイムアウト・不正な形式の場合も現在の一覧を維持します。
件数上限はルアー・リール各5000件、文字列は各500文字。重量未設定はnullで扱います。
空の一覧は正当な更新として扱い、「その他」を引き続き利用できます。
ルアーの「あり」条件はAPI・アプリ・保存済みキャッシュの読み込み時にも適用します。
初回取得前は所持を確認できないため、固定ルアー候補は表示せず「その他（自由入力）」を利用します。
端末で明示的に登録したカスタムルアーは引き続き使用できます。
圏外では最後に取得した「あり」の一覧を使用するため、シート変更の反映にはオンライン更新が必要です。
「更新済み」「キャッシュ使用中」「初期マスター使用中」などの状態を表示します。
キャッシュ書き込みが失敗しても、取得した一覧はその起動中利用でき、警告を表示します。

localStorageのキー:
  fishing-distance-log-v1             既存履歴。起動・マスター更新では書き換えません。
  cast-distance-master-v1             正常取得したマスターと取得日時。
  cast-distance-master-endpoint-v1    この端末のAPI URL。
  cast-distance-custom-tackle-v1      端末で登録したルアー・リール。
  cast-distance-selection-v1          前回の選択と入力値。

旧履歴の日時・名前・距離・メモ・計算条件を変更する移行処理はありません。
新規記録には管理ID、取得元、重量、カラー、巻上長の根拠、基準巻上長を追加します。
CSVの先頭9列は従来どおり。追加列は末尾8列で、旧記録の未設定値は空欄になります。
計算式と丸めも従来どおり。45回 × 89cm × 100% → 40.1m。
履歴の保存に失敗した場合は、表示中の履歴も変更しません。

Service Workerはcast-distanceの同一スコープだけを扱います。
v4でHTMLとJSをまとめてプリキャッシュし、APIの外部通信は捕捉しません。
古いアセットキャッシュの削除でlocalStorageや他アプリのキャッシュは削除しません。
今後アセットを変えたらsw.jsのCACHEバージョンも上げてください。
新画面が出ない場合はオンラインで一度開き、更新完了後に再起動してください。
サイトデータの削除は不要です。別端末・別ブラウザには自動同期されません。
ブラウザのデータ削除では履歴が失われます。CSVは定期的に保存してください。

検証方法と結果（2026-11-15）
----------------------------
Node.js 18以上。追加パッケージなし:
  node --test cast-distance/tests/pwa.test.cjs

25件成功:
既存の計算・範囲制限・保存失敗・削除・CSV・manifest・SW検証を維持。
マスターの成功/失敗/タイムアウト/不正応答/遅延応答、キャッシュ・初期一覧への復帰、
選択と自由入力の復元、重複排除、基準値と手動値、「あり」限定と旧状態の除外、
ID変更・削除後の履歴保持、旧履歴と新履歴が混在するCSVを追加検証。
Apps ScriptはGoogle APIをスタブ化し、指定範囲以外を読まないこと、
ID維持、データ抽出、callback検証、読み取り専用スコープを確認します。

任意の実ブラウザ確認（開発確認用。アプリにPlaywrightは不要）:
  node cast-distance/tests/browser-smoke.cjs <Playwrightまたはplaywright-coreのモジュールパス>
PlaywrightとChromium、および旧版のGitコミット50fe63bがローカル履歴に必要です。
GitHub Pagesと同じサブパスをlocalhostで配信し、390px幅で確認します。
結果: Chromiumでv2→v4の実更新、旧履歴保持、「なし」の非表示、CORSヘッダーなしのJSONP取得、
カスタム登録、CSVダウンロード、通信遮断後のディレクトリURL・index.html再起動、
巻上長・計算結果・キャッシュ利用・横スクロールがないことを確認しました。
画面画像はOSの一時フォルダ/cast-distance-browser-checkに出力します。
Googleの応答は模擬しており、実Google API・公開権限はこのテストの対象外です。

実API確認（2026-11-15）:
所有者がデプロイしたAPIへの匿名GETでHTTP 200と、返却ルアーの状態がすべて「あり」であることを確認しました。
端末の接続先URL設定は「マスター接続設定」で行います。

残る実端末の確認:
- 公開PWAからの実Google API取得。
- シート更新→「マスター更新」で反映されること。
- Android Chrome / iPhone Safariへのインストールと実端末の圏外起動。

「あり」「なし」への対応更新:
既存のApps Scriptも更新済みの「アプリ用マスター」を読むため、シート側の抽出条件が反映されます。
PWA側でも「あり」を検証するので、既存デプロイのままでこの表示制限を利用できます。
同梱Code.gsにも「あり」限定を追加しました。API側でも防御的に絞りたい場合は、
Code.gsをコピーして既存デプロイを新バージョンに更新してください（URL変更は不要）。
